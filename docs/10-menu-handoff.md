# 菜单交接时序和表现

当前实现：v16，2026-11-13。共享核心同时供微信和浏览器使用。整体美术、布局、14种食材与20道菜沿用原工程；菜单交接、上菜与结算覆盖旧v13行为。收料图标按最新试玩反馈保持原色，仅用绿色勾标记已收。

依据已核对的上级目录 `dapaidang-ai-update-v16/` 中的 `v16补充说明.txt`、`data/v16-patch-spec.json`、17.5秒正常速度视频、状态对照图和 `src/v16-animation-reference.js`。该源码是固定时间轴参考，本工程采用真实选牌、入槽、配方确认和厨房事件驱动。**本工程没有收入目标；全部材料用完且最后上菜完成才通关**，不采用补充说明中的收入达标通关，也不使用128、323、00:14等演示常量。

## 交接时间轴

`t=0` 为最后一份食材已到槽、引擎确认配方的时刻，不包含之前0.30秒的取菜飞行。

| 相对时间 | 业务与表现 |
| --- | --- |
| 0 | 从buffer一次性扣除配方itemId，立即释放格位；创建独立厨房任务，锅空即可开始。收入不变。 |
| 0～0.20秒 | 已消费食材的视觉副本从原备菜位收走一次。忙锅时收向小挂牌附近，原格立即可以放新食材。 |
| 0～0.28秒 | 旧卡轻抬3设计像素；食材0.11秒收拢淡出，盘盖0.12秒显现，盖0.16秒从上方10像素落下；文案“交给大厨啦”。 |
| 0.28～0.42秒 | 旧卡的桌号、菜名、奖励、夹子、餐盘和盖子整体上移34、缩至0.935并淡出。相邻卡不动。 |
| 0.42秒 | 原卡槽完整显示下一张菜单，透明度1，可以接料、匹配已到槽材料。有限队列耗尽时显示“本桌已上齐”。 |
| 0.42～0.54秒 | 新卡从上方10像素轻落原位；透明度始终1，不锁输入。 |
| 新卡出现后0.75秒内 | 很淡的暖色边缘逐渐消失；没有“新”贴纸、小票折叠或大状态条。 |

三张菜单各自保存 `matchedAt/replaceAt/bornAt`，独立推进，不共享换单等待队列。即使三桌连续配齐、锅忙或已有菜在送达，新菜单仍按各自的0.42秒期限显示。若新菜单所需材料已经备齐，可以在显示时确认；下一代菜单仍须经过自己的交接期限，不能在隐藏状态连续吞料。

盘盖只在配齐后出现，表示交给大厨。盘位中心X为 `200+slot×264`，盘基准Y385、盖面Y387；盘宽211、内圈半径88.62，盖缘半径85。现有透明PNG先按manifest bbox裁出可见物体，再等比绘制：盘图中心Y为baseY+8；盖图可见宽170、中心Y为faceY−21.5，盖缘落在盘内圈，左右同心。盖子随旧卡退出，送达时不再揭盖。

## 菜单与厨房分开保存

| 数据 | 生命周期与职责 |
| --- | --- |
| `orders[0..2]` | 当前三张菜单：`collecting → confirming → exiting → 下一张collecting`；有限队列结束为 `completed`。仅 `collecting` 可匹配材料。 |
| `jobs` | 所有已交单的独立任务：`queued → cooking → delivering → served`。可以跨越原卡槽的多代菜单。 |
| `queue / wok / deliveries` | 任务的FIFO待炒、唯一炒锅、并行送菜引用。出锅立刻释放锅。 |

每次创建引擎产生新的 `levelId`，包括重开同一关。厨房任务的 `jobId/orderId/table/recipeId/ingredients/payout/recipe` 以及来源 `originSlot` 在创建时保存为只读快照；菜单后续更换桌号、配方或显示状态不会改变旧菜。`originSlot`只记录原位置，不参与结算。

`recipeAccepted`立即消费材料，并附消费itemId、食材副本、原订单身份、jobId、是否排队及换单期限。`cookingStarted`与`dishOut`只改变厨房任务。`dishServed`使用 `levelId/jobId` 幂等键及任务金额快照入账一次，不读当前菜单桌号、不写回新菜单、不设新卡退场时间。新关拒绝旧levelId任务。

正常制作始终为入锅0.28＋翻炒0.60＋倒菜0.32，共1.20秒。当前没有启用连续加速。真实点击没有0.75秒冷却，只受几何遮挡、7格 `buffer+incoming` 容量和暂停/结束状态约束。

## 材料与收料标记

菜单内已收到与仍缺少的食材图标均使用原始素材，保持原色、正常大小与alpha1；已收仅添加不透明的绿色小勾，进度同步更新。不淡化、不降饱和度，不给食材新增小框。

浏览器与微信共用同一绘制逻辑，菜单与食材台使用同一份原色食材图片，不生成或载入收料淡化派生图。原始素材与哈希不变。满备菜格完整铺色，食物按bbox比例绘制，空格与满格互斥绘制。消费、撤回或暂存后，剩余已到槽食材保持原顺序立即向左补齐；暂存取回接在已到槽食材之后。在途预约依次排在已到槽食材右侧，落点随补齐更新，仍计入7格容量。先固定已消费副本的原槽位置再补齐；同一时刻多桌消费各自从原位置离开，不因补齐重复拉料或共用起点。

消费后的视觉副本在 `recipeAccepted` 时记录原槽位置，0.20秒内收走；每份错开0.012秒、弧高38、容器69×89缩至22×24，末段淡出。空锅目标为 `(742+(i−1)×18,1405)`，忙锅目标为 `(458,1355)`。排队任务开炒只从任务配方生成锅内碎料，**不再从已腾空或被新食材占用的格位拉一次旧料**。

现有小挂牌位于 `(337,1333,242,44)`，显示“自动快炒”“快炒中”或“快炒中 · 待N”，不新增队列卡。

## 成品路径与入账

全部坐标为928×1695设计坐标，绘制与命中共用安全区变换；飞行层不接收触摸。

| 相对出锅时间 | 路径与表现 |
| --- | --- |
| 0～0.62秒 | 从(837,1484)立即上行至Y1208；X沿起点到固定出餐点(735,188)的方向插值。宽起始145。进度u>0.40时，`f=clamp((u−0.40)/0.60)`，宽145→15、alpha1→0。 |
| 0.62～0.78秒 | 紧接上部显现，从(751,198.5)到(735,188)，宽65→96；前0.07秒完成淡入。无隐形穿越、静止或额外等待。 |
| 0.78秒 | 真实送达，按原任务金额入账一次。锅早在出锅时释放，可与下一道制作并行。 |
| 送达后0～0.16秒 | 成品从固定出餐点向右20、上8，缩小8%并淡出。 |
| 送达后0～0.45秒 | 金额轻反馈；收入牌0.42秒小幅回弹，最大1.018。 |

固定出餐点在收入牌旁，成品不落到新菜单、不遮住夹子，也不触发第二次换单。锅空时，从配齐到真实送达共1.98秒；排队时加上实际FIFO等待，菜单交接仍是0.42秒。

## 库存、结束与生命周期

补单有效库存只包括未取牌、备菜、在途和暂存；已经扣料进入厨房的材料不得再次算作可用。正式关卡沿用材料配平的有限三桌 `orderPlan`，每桌按计划补单且耗尽停止，所有跨桌未来配方均检查子集冲突。无有限计划的练习入口也按有效库存和当前收料菜单的配方冲突过滤候选。

有入槽、交接、排队、炒制或送菜任务时不判失败；暂存不空时不判库存耗尽。所有食材用完，备菜、在途、暂存为空且全部厨房/交接任务完成，才通关并冻结用时。新空菜单不影响通关。收入仅记录，不设目标、不按速度评星。

暂停/后台冻结引擎时间与视觉进度，恢复重置帧时间。重开/换关替换引擎并清空效果、视觉槽位、工具状态、暂存、预约和任务；事件与结算同时核对levelId。

经营V1在局内流水之上增加独立永久钱包：`levelWon`之后按持久化尝试ID核对、一次性提交首通或每日重玩奖励，同时提交菜谱和活动；不改变`dishServed`流水结算。成功弹窗增加本次入账与钱包余额，支持回小摊；暂停中回店需确认放弃本局。存档失败阻止换关与回店，重试不重复发钱。详见11、12文档。服装、木台、灯具、菜单与锅盘装饰不改变本文件的配方、时序和素材辨识。

## 验证与复现

```sh
npm run build:wechat
npm test
npm run serve
```

浏览器打开 `http://127.0.0.1:4173/platforms/web/`，微信开发者工具导入 `platforms/wechat/`。`game/`为构建产物，勿手改。当前生成主包约3.23 MiB，含38张原色运行图片，在项目4 MiB预算内。

2026-11-13结果：

- 单笔真实事件链路：立即扣料、0.28秒确认、0.42秒换单、0.54秒落稳、1.20秒制作和0.78秒送达，入账一次。
- 三桌错时连续配齐时独立换单、单锅FIFO、出锅即开下一锅；同一卡槽五代菜单和旧任务金额/配方快照不串单，重复送达不重复入账。
- 隐藏后继不提前吞料；备菜/在途/暂存计入有效库存，已交厨房材料排除；暂停、重开及换关覆盖确认、退出、炒制和送菜阶段。
- 四档完整关卡以0.01秒间隔尝试快点，仅满容量时等空格，40份材料各消费一次，实际总收入与有限计划一致，无道具通关。
- 渲染输出检查：已收萝卜与缺料使用同一原色图片，大小与alpha1保持一致，已收仅加alpha1小勾；盘盖同心且保持比例；新卡无盘盖，成品位于固定点；排队开炒不再次拉旧槽。
- 备菜左补齐检查：消费后余料按原顺序落在最左侧；在途预约、暂存取回与撤回不留空格或重叠；同刻多桌消费及慢帧仍保留每份已消费材料的原槽起点。
- 常规回归：默认100关、四档400个种子材料与通关、192条策略与真实引擎一致性，以及微信无DOM启动、安全区、生命周期与38张图片加载均通过。固定策略难度基线未变（详见09文档）；本次未重跑历史10,000关扩样。
- 浏览器实点番茄与鸡蛋：缺料进度更新，新菜单出现后旧菜送达，收入0→32，无控制台警告/错误。另实点萝卜确认已收后仍保持橙色并显示绿色勾和1/3；微信入口模拟触摸回归确认菜单与食材台使用同一原色萝卜图、alpha1与绿色勾。真机触摸、性能和真人观感校准仍待验收。
