# 灯火大排档经营需求与验收

版本：经营 V1，2026-11-13。适用于微信小游戏与浏览器试玩。核心目标是在现有配方消除之上建立持续可见的装扮、菜谱收藏和夜市活动成长。本文与[运营与经济配置](12-operations-and-economy.md)共同定义经营产品；局内规则仍以 AGENTS.md、09 和 10 文档为准。

## 产品范围

经营循环为：完成配方消除，首通流水存入金币钱包，购买并搭配小摊与厨房外观，积累菜谱和主题收藏，再选择下一个愿望。每次完整通关也能推进每日奖励和已开启的活动册。

不建立熟客、好感度、来信、员工数值养成、采购库存或离线收益。背景大厨只提供视觉表现。外观不改变容量、菜价、配方、制作时长或难度。主招牌始终为五字“灯火大排档”。

本次交付包括四个可操作页签、局内往返、金币与购买、永久装备、菜谱记录、四册活动、每日奖励、相册及本机存档。经营页使用现有食物素材和程序绘制的暖夜市场景，主题通过颜色、棚布图案、灯具形状、场景水岸、摆设和厨具装饰区分。局内以v12完整交付版纯背景和组件为基准，主题装饰保持相同UI坐标；闯关表现与验收见10文档。

视频奖励保留真实完成回调接入口；当前没有广告单元配置，界面不显示视频领取按钮，也不模拟完成。付费商品、账号、云同步、图片导出和对外分享不属于本地原型的可用能力，上线工作见运营文档。

## 局内规则与经营边界

保留三桌有限补单、40份材料、7格备菜及飞行预约、暂存容量2和工具次数1/2/1。配齐立即扣料，独立厨房任务继续FIFO制作与并行上菜。只有所有食材与任务全部完成才通关，不设置收入目标，也不按速度评星。

上菜只累加局内流水；主线首次通关把完整流水转入永久钱包，失败或主动离开不转存。重玩仍显示实际局内流水，但永久钱包仅按每日重玩和每日任务规则发放。结算须同时显示本关流水、本次永久入账和钱包余额，避免把展示流水误认为再次发钱。

成功结算先持久化，再允许下一关或回店。存储写入失败时，内存金币、拥有物品、每日领取标记和活动进度全部不提交；保持本关成功状态，提示玩家重新点击按钮重试。下一局开始生成新的持久化尝试编号，旧局回调不再能结算。

## 装扮与购买

开局完整赠送基础9件。金币主题分别在首通1/20/40关后开放，主题开放与关卡推进不要求先消费金币。买后立即装备对应位置；拥有状态和装备状态独立，混搭不影响套装收藏。

购买弹层展示完整名称、试装场景、价格、购买后余额与“确认购买并装备”。金币不足时说明差额；未达到关数时说明解锁条件。已拥有、活动获取和菜谱获取物品都不得再次扣款购买。

程序绘制的场景区分棚布图案、灯具形状、环境配色、水岸与摆件。厨房和大厨外观进入真实闯关画面：锅沿装饰、餐盘边缘、木台色、菜单装饰、大厨服装及灯具。食材素材、原色、菜谱与盘盖交接时序保持不变。

## 通关与失败流程

首次成功结算：流水入账与每日首胜自动保存，结算后引导回店，展示第一串灯500金币；玩家可以试装并购买。第一关默认实际流水636，含每日首胜共786，因此首次购买可达成。引导可以关闭，首页仍保留愿望入口。

后续成功结算：默认“下一关”，次按钮“回小摊看看”；显示本次入账和一项新的收藏反馈。回店和下一关均不重复领取任何奖励。失败提供免费再试与回店，已存钱包、装备和收藏不回滚。

局内暂停：可恢复、切换减少动效、重开或回店。主动离开进行中的牌局时确认，提示会重新开局，永久数据保留。返回主页释放当前会话；下次新建引擎，工具、预约、暂存、厨房和效果均从零开始。后台暂停和恢复重置帧时间。

## 菜谱与纪念

20道菜的配方来源仍为recipes.json。首次成功结算有制作记录即点亮；每道菜的累计阶段为1份“初次上桌”、30份“拿手家常”、100份“小摊招牌”。仅主线首通和每日首次奖励重玩的出菜记录累计份数；重复刷同关不会无限增加收藏熟练度。

点亮6道自动获得手绘菜单，12道获得青花餐盘，20道获得完整菜谱纪念框。主题拥有3/6/9件分别生成贴纸、相框和主题纪念。每完成20关生成章节纪念。活动册3和10进度生成贴纸和相框。纪念依据已持久化记录派生，自动可见，无需手动领取。

手动照片保存装备ID、日期和完成关数，不保存大体积位图。相册重绘照片时使用当时的装备，而不是当前装备。照片只在本机应用内查看；删除需要二次确认，纪念奖励不能删除。导出图片及自由选框属于后续扩展。

## 数据与平台

核心经营规则在shared/core/profile.js，配置在shared/data/progression.js，会话路由在shared/runtime/stall-app.js，绘制在shared/rendering/stall-scene.js和stall-art.js。共享层不调用DOM或wx。

存档键为lantern-stall-v2，版本2。字段包括金币、首通关卡集合、已拥有物品、九个装备位置、愿望、菜谱份数、每日状态、活动四册进度、选中册、营业天数、手动相册、账本、尝试序号和减少动效设置。当前牌局不恢复。

旧lantern-progress-v1迁移已解锁关数，旧lantern-settings-v1迁移减少动效；历史金币与历史出菜记录没有可靠来源，因此从0开始，不补发。迁移后的历史关数仍用于主题与功能开放。错误或未知的物品ID移除，非法金额与计数恢复默认；旧档不主动删除。

浏览器使用localStorage，微信使用同步本地存储；一次写入完整快照，成功才替换内存状态。尝试编号开始前持久化，完成时核对编号和关卡，首次通关以关卡集合去重。每日按北京时间，设备日期倒退不重新开放奖励。当前本机日期不构成服务端防作弊，清存储和换设备不具备保护。

浏览器难度直达链接保留。请求未解锁关卡时作为独立试玩，不发经营奖励，不解锁后续主线；正常首页始终进入下一未完成关卡。

## 验收标准

1. 默认启动进入小摊，四个页签均能操作，未开放功能有明确关数提示。微信无DOM启动并共用安全区变换。
2. 真实第1关通关后钱包786；重复回结果不增发。购买暖红灯串后余额286，灯具立即变化，重新载入装备与金币一致。
3. 同一天重玩第一次入账200，第三次完整通关触发每日150，之后重玩无基础金币；跨日恢复每日资格，日期回拨不重复领取。
4. 购买同物品、金币不足、未解锁主题、未拥有装备和活动物品直购均失败，不能负余额。
5. 存档写入失败不消费、不发放、不改变领取状态，成功重试仅结算一次。
6. 首通与每日首次奖励重玩累计真实served任务；失败和放弃不累计。20道配方与14种原素材保持一致。
7. 活动每日前三次可参与通关各+1；6/14自动发装扮，四册完成获得大厨服；旧册跨周保留。
8. 相册保留拍摄时装备；确认删除只删除选中照片。章节、主题、活动和菜谱纪念可查看。
9. 暂停/后台不推进局内任务；回店再开、重试和下一关清空所有旧任务。最后上菜仍是唯一通关时机。
10. 构建后完整测试通过；微信主包仍小于项目4MiB预算。真机触摸、性能、音频、云同步和正式商业化单独验收。

自动检查入口：npm run build:wechat后npm test。新增经营回归在tests/verify-progression.cjs，原菜单交接回归继续执行。
