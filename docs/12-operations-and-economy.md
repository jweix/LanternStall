# 灯火大排档运营与经济配置

版本：经营V1，2026-11-13。面向产品、美术、开发和运营，用于配置金币、常驻主题、夜市活动、内容更新与发布验收。现有实现配置集中在shared/data/progression.js；页面和行为见[经营需求与验收](11-product-requirements.md)。

## 资源和目标

唯一消费货币为金币，用于永久装扮。首通关数、菜谱制作记录、活动进度是独立不可消费进度，不兑换金币，不改变关卡能力。玩家可以不买装扮而持续闯关，皮肤不提供强度。

短目标为攒够一件物品；中目标为集齐主题、完成活动册与点亮菜谱；长目标为章节纪念和自己的小摊搭配。页面只突出一个当前愿望，其他目标自然累计。

金币钱包初始0。失败、重开或退出不转存本局流水，也不扣永久金币。每日奖励自动发放，不设置登录领金币和强制分享奖励。视频当前未配置，不显示入口；不得以倒计时或模拟播放代替实际广告完成凭证。

北京时间每天0点更新资格，按成功结算时所在日期归属。暂停时跨日，恢复完成后计入新的一天。设备日期回拨沿用已保存日期，不能重新领；正式上线应使用服务端日期校验。

首通去重依据主线关卡号，不能因生成器版本、美术升级或客户端重载重新发放历史首通收入。生产多章节扩展如果变更关卡标识，需先设计内容ID迁移。

## 收支基线

现有默认第1至120关经真实引擎见证回放，累计流水95700，平均797.5，最小636、最大850。这里只是关卡完成收入，不代表真人胜率或局时。运营以每次首通约800金币估算，再用真实配置重算。

| 假设 | 首通收入 | 每日奖励 | 合计 |
| --- | ---: | ---: | ---: |
| 第一天4次首通 | 3039 | 300 | 3339 |
| 每天4次首通，7天 | 22284 | 2100 | 24384 |
| 每天2次首通，30天 | 47892 | 4500 | 52392 |
| 每天4次首通，30天 | 95700 | 9000 | 104700 |

首关636加首胜150等于786，第一件500可立即购买。第一天买灯串、棚布、桌椅共3100，余额239。每天4次首通一周可完成暖红套；30天完成暖红和竹影共72000后剩32700。每日重玩30天最多增加6000，视频满额最多增加18000；对应30天最高128700，仍低于首发常驻总价144000。

真人无法稳定达到上述首通频次时，应以真实新关完成速度复核价格和活动条件。不要把关卡变难、提高道具消耗或售卖容量作为消耗金币的手段。常驻金币没有自动重置与过期。

## 菜谱和相册奖励

每菜1/30/100份对应初次上桌、拿手家常、小摊招牌。主线首通与每日首次奖励重玩计入菜品份数，其他重玩不累计，失败不累计。配方列表与关卡生成器保持独立，不为了收藏临时替换当前订单。

| 条件 | 永久奖励 |
| --- | --- |
| 点亮6道菜 | 家常手绘菜单 |
| 点亮12道菜 | 好味道青花盘 |
| 点亮20道菜 | 完整菜谱纪念框 |
| 常驻主题拥有3/6/9件 | 主题贴纸、相框、主题纪念 |
| 每完成20个主线关卡 | 章节纪念 |

奖励按已保存状态派生或发入拥有列表，不要求玩家点击领取。纪念图是收藏插画，可查看完整主题风貌；它不授予尚未拥有的实际装备。手动照片保留真实拍摄时装备，最多24张。

每册14局，每天两局需要7天，每天三局需要5个游玩日。四册共56局，重玩可以参与，失败不扣进度。切换册、跨周、客户端重载都不清零；当期与往期在本版展示同一套已开启的活动册，尚未上线后续期。

当前进度结构固定四册。运营不得直接把event.id与奖励物品替换成下一期并复用旧数组；新增一期时必须按活动ID保存进度、保留旧配置，并完成存档迁移。这是下一期上线前必须开发的接口，不能只换文案。

## 内容生产和运营节奏

首发常驻为3套27件，另有基础9件、活动9件、菜谱2件。程序主题表现已可操作；正式投放前可在相同物品ID下替换精修素材，保持价格与拥有记录。

建议四周一个主题制作批次：明确风格与九个位置，先完成主场景与厨房可见差异，再导出纪念插画和相框。每周主推一本活动册，往期随时继续。首月先验证四个页签和首次装扮，不同时叠加排行、公会或连续失败促销。

按每天4次首通，28天约产出9.8万基础金币。持续运营时，每四周补充约10万金币的可选收藏商架，可由新主题与旧主题变体共同组成。这里衡量可购买内容的总标价，不要求玩家全部买完。同步观察未拥有愿望数量、首个购买等待关数与金币余额分布。玩家适量存钱是正常行为；库存不足时优先补充可感知的新外观。

每周检查：首购路径、购买失败、存档失败、金币异常增发、未解锁主题误售、活动进度丢失和难度卡点。每四周复核：金币产消、主题购买分布、活动完成人数、回店率与次日回访。难度调参遵循09文档，不能仅凭经营指标改动生成器。

## 指标定义

当前没有联网埋点，以下为生产接入时的事件契约，不代表已有统计平台。

| 事件 | 必要字段 | 用途 |
| --- | --- | --- |
| level_start | 关卡、尝试ID、首通/重玩、生成器版本 | 进入与尝试分布 |
| level_end | 尝试ID、成功/失败/放弃、有效局时、流水 | 完成率与卡点；有效时间不含暂停后台 |
| wallet_change | 来源ID、金额、前后余额、关联关卡或物品 | 收支核对与增发排查 |
| outfit_preview | 物品、来源页面、是否拥有 | 了解外观兴趣 |
| outfit_purchase | 物品、价格、购买后余额 | 首购与主题购买转化 |
| outfit_equip | 位置、物品 | 装扮是否持续使用 |
| tab_view | 页签、进入来源 | 回店与功能使用 |
| event_progress | 活动ID、册ID、前后进度、奖励ID | 活动参与与留存 |
| save_failed | 操作种类、存档版本、错误类型 | 持久化质量 |

留存以同一用户首日开始，次日/第7日发生有效游戏或经营操作为回访。分别观察闯关用户、首次购买用户、活动参与用户的回访，不能仅凭人群差异认定功能带来因果提升。试验需要相同难度与流量条件。

## 上线边界和发布清单

本机存档已经贯通，尚无账户和云备份。投放前需确认是否接受设备清理导致进度丢失；若接云端，购买、钱包和奖励须以服务端事务与唯一来源ID核对。不要在客户端存档中放支付密钥。

当前没有广告单元与支付配置。只有平台确认完整播放的回调才能调用补贴接口；广告关闭、加载失败、重复回调、换关、跨日和存储失败必须单独回归。后续付费主题明确交付永久外观，价格另行测试；首版不出售金币倍率与容量优势。

发布检查依次为：完整构建与测试、真机触摸与安全区、后台恢复与低帧性能、本地存储失败、资源体积、音频和减少动效、平台审核与用户存档说明。视觉美术与真人难度仍需实机验收，不能用自动见证通关代替。
