# 灯火大排档 UI 风格设计

统一风格是**暖夜市、家常小炒、圆润的 2.5D 食物与器物**：深蓝绿夜街衬托红棚布和暖灯笼，蜂蜜与焦糖色木台承托奶油色界面，食物保持鲜亮原色。整体应有小摊的烟火气、食欲和亲近感，同时让材料、订单和操作清楚可辨。

局内基准仍为v12完整交付版；**经营四页的基准更新为2026-11-14用户确认的整体重构视觉稿**，原图完整保存在[四页视觉参考](../reference/lobby-redesign-2026-11-14/)。四页按887×1774原稿画幅绘制，闯关仍使用928×1695，两者各自等比contain，绘制、原生触摸和浏览器无障碍按钮共用对应坐标。

经营首页突出大摊位、大厨与朱红色开张入口；内容页压缩品牌区，使用木质结构和奶油内容卡。采用独立环境、摊位物件和可复用空白组件拼装，文字、金币、菜谱份数、拥有／使用中、关卡、活动和按钮行为由真实业务驱动。禁止使用含有按钮、列表槽位或预览效果的整页背景。不是把384、29关、价格600／1000或手动领取写入生产存档。具体交付和差异见[四页接入说明](14-lobby-redesign.md)。

## 视觉基准

主招牌固定为弧形五字“灯火大排档”。棚布、灯笼、木架、木台、桌布和凳子共同构成夜市语境；食材、锅盘、金币与按钮使用同一套圆润、略有厚度的表现。背景保留夜街纵深、模糊灯光和暖色反射，前景交互物清晰、明亮，装饰不抢食物和操作的注意力。

画面主要依靠材质和受光形成层次：上部奶油高光，下部蜂蜜或焦糖压暗，接触处有柔和投影。食物形体饱满、特征概括，高光柔和，缩到手机尺寸仍能辨认。锅具保留深灰金属与木柄，金属反光克制。

旧 v13 底图、旧演示和素材图鉴的排版不作为新页面的风格基准。不要沿用其中过时的收入目标、永久首卡高亮或厨房挂牌。

## 色调与颜色分工

**大面积采用木色和奶油色，深蓝绿承担环境衬底，红色与金色集中在品牌、灯光和关键反馈。** 食材自身的红、绿、橙、黄承担内容辨识，不把每种食材颜色扩展成一套卡片底色。蓝火是厨房的局部冷色点缀。

下表取当前共享绘制的颜色。背景插画的棚布红、灯光和夜街有纹理与受光变化，继续使用原素材，不用单一色块替代。

| 用途 | 颜色 | 使用方式 |
| --- | --- | --- |
| 夜色衬底 | `#253B3B`；局内画布外侧 `#1B3937` | 背景、画幅外留白或场景深处；前景正文使用浅色容器承托。 |
| 奶油面板 | `#FFF5DB → #FFEBC8 → #F5D7A9 → #E0AE73` | 从上到下渐变，停止点为0／25%／80%／100%；用于订单、内容卡和普通面板。 |
| 食材牌与满备菜格 | `#FFF4DA → #FFE9C2 → #EFCF9F` | 停止点为0／55%／100%；所有原色食材共用中性奶油底。 |
| 收入等小挂牌 | `#FFF0CF → #FFE4B7 → #E8BD83` | 停止点为0／50%／100%；面积小、对比清楚，保持轻盈。 |
| 木质面板 | `#E4AA67 → #D99955 → #B97439 → #A65F2B` | 停止点为0／18%／80%／100%；用于木框、木牌及承托结构。 |
| 木台内涂层 | `#B97A43 → #C4864B → #A46230` | 停止点为0／50%／100%，叠低对比木纹；保留背景原有木台外沿。 |
| 正文墨色 | `#60331B`、`#633316` | 深棕色标题、正文和计数，避免在暖底上使用大面积纯黑。 |
| 次级文字 | `#875332`、`#805332` | 标签、说明和次要操作；仍须保持手机尺寸可读。 |
| 品牌与收入强调 | `#B34423`、`#AC4223` | 通关标题、重点金额等局部强调；棚布和主招牌的红色跟随原图。 |
| 金币与奖励 | `#FFF2A0 → #FFD56C → #D5952F` | 通过渐变和高光表现圆润金属，不使用荧光黄铺满面板。 |
| 完成标记 | `#72A33C`，勾线 `#FFF7DC` | 绿色圆底加浅色勾，配合进度或状态文字表达完成。 |
| 新内容轻提示 | `#F2B75E` | 细暖边、短暂提示；不让默认卡片一直高亮。 |
| 奶油与木框亮边 | `#FFF7DF`、`#F8CF94` | 少量内沿高光，帮助表现厚度；通常2～3设计像素。 |
| 炉火 | `#4ED1FF`及素材中的浅蓝高光 | 局限于炉火，不扩展成全局按钮和导航主色。 |
| 弹窗遮罩 | `#21180FBA` | 带棕色的深色遮罩，约73%不透明度，压低背景后突出面板。 |

当前下一关主按钮另用 `#FFE6AF → #F8CC87 → #EAB16A → #D3904C` 蜂蜜渐变，以 `#9D5628` 承托底部厚度。经营页的主操作改为原稿的暖朱红厚按钮；次操作使用奶油色。局内按钮继续保留既有样式。

## 材质与形状

容器使用柔和圆角、浅亮边和向下的投影，形成可触碰的厚度。木质承担外框与承托，奶油色承担信息阅读，金属主要出现在锅、盘盖和金币。木纹只作低对比细节，不穿过文字和食物形成干扰。

以下为现有组件的设计像素，可作为新组件的比例参考，不要求把所有尺寸机械统一：

| 组件 | 现有表现 | 延用方式 |
| --- | --- | --- |
| 普通面板与订单卡 | 圆角约23～30；面板投影 `#51230C55`，模糊10、向下6 | 明亮奶油面与柔和投影成组使用，内部通常不再套多层底板。 |
| 食材牌 | 圆角约短边的18%；底部厚度6；投影 `#69361248`，模糊6、向右2、向下5 | 图案居中，亮边细，保持食物与卡面清楚分离。 |
| 备菜格 | 69×89、圆角18；空槽为凹陷渐变，满槽整格铺奶油色 | 凹槽与满格互斥，满格不能再套一张缩小卡片。 |
| 道具按钮 | 原纹理圆角厚按钮，图标与大字并列，次数为小椭圆角标 | 复用原资源的纹理、体积和组合比例。 |
| 通关面板 | 圆角木质外框、奶油内页、弧形标题木牌、金币装饰 | 层次集中在外框和标题，正文区域保持干净。 |

木台内涂层顺着原背景的椭圆弧边界绘制；扩展场景时同样尊重器物的轮廓和透视。避免厚黑描边、硬直角商务面板、玻璃拟态、霓虹发光边框、过强塑料反光和写实油腻摄影。

## 字体与信息层级

局内字体有圆润、亲切的手写或楷体气质；经营页只有固定品牌标志保留美术字；页面标题、按钮、名称和动态文字采用清楚的700字重中文无衬线字体。当前闯关绘制按 `HanziPen SC → Kaiti SC → STKaiti → PingFang SC → sans-serif` 回退；经营动态文字使用Hiragino Sans GB／PingFang SC／Microsoft YaHei／Noto Sans CJK SC回退，字符和数字不横向拉伸。跨平台补充字体时，可参考[设计令牌](../shared/data/design-tokens.json)中的 `Microsoft YaHei`、`Noto Sans CJK SC`。字体实际可用性和字宽需要在目标设备核对。

以928×1695设计画布为准，现有字号层级如下：

| 信息 | 当前字号或处理 |
| --- | --- |
| 弧形主招牌 | 使用原背景中的五字美术字，保留其弧度和受光。 |
| 弹窗主标题／核心收入 | 通关标题65，核心收入86；失败标题49。 |
| 主操作 | 下一关48，长文案39；原纹理按钮保留烘焙文字，不再重画一遍。 |
| 页面区块与菜名 | 食材台、订单菜名36。 |
| 常规状态与计数 | 备菜标题32；桌号、订单奖励和配料进度经现有辅助函数绘制时至少32。 |
| 收入小挂牌 | “收入”27，金额30；这组紧凑字号独立保留。 |
| 辅助说明与角标 | 多为26～31，先保证可读，再控制占位。 |

新页面先区分标题、主要内容、关键数值、操作和辅助说明，再选择字号。金额或主操作可以突出，说明文字保持克制。长菜名使用 `displayName`；其他长文案应测量字宽，选择换行或合适的短文案，不横向压扁字体，也不为了塞满文字把整页字号不断缩小。

## 组件与状态表达

订单、列表、页签和弹窗应属于同一个小摊：奶油卡承载信息，木框承托区域，图标和食品承担内容辨识。卡片保持足够留白，避免把菜名、价格和每个图标都套入独立小框。

| 场景 | 共用的视觉处理 |
| --- | --- |
| 内容卡 | 奶油渐变、深棕文字、圆角和柔和投影；同级卡默认同权。 |
| 主操作 | 经营页使用原稿朱红厚按钮；局内保留蜂蜜／奶油按钮。图标与动词清楚，每个操作区突出一个主要动作。 |
| 次级操作 | 较轻的奶油小牌或深棕文字，层级低于主按钮。 |
| 选中项 | 局部暖边、底色或字重变化，并保留可辨认的状态标记；整页不同时闪烁。 |
| 已完成 | 绿色勾加数量或文字；菜单已收食材保持原色、原大小、alpha1。 |
| 被遮挡的牌 | 使用暖灰褐、低饱和暗牌，解除全部遮挡后恢复原色；暗牌处理仅服务遮挡状态。 |
| 未解锁或不可用 | 使用明确的锁、条件或不可用文案，可辅以弱化容器；不与“已收到食材”混用同一种灰暗表现。 |
| 成功弹窗 | 木框、奶油内页、品牌红标题、金币与主结果；次要操作以较轻文字呈现。 |
| 提示与错误 | 使用短句说明当前状态和可执行动作，颜色作为辅助，避免只靠红绿区分。 |

图标延用圆润、略有厚度的器物造型，例如箱子、灯泡、回转箭头、齿轮和扬声器。已有图标优先复用；新增图标需统一光照、圆角和墨色，避免混入 Emoji、系统细线图标或风格不同的素材。

## 布局与页面延用

闯关按“品牌和收入 → 三桌订单 → 食材主体 → 备菜与厨房 → 道具”组织注意力。其他页面延用这种清楚的主次关系：先识别所在页面，再看到主要内容和当前行动，装饰围绕内容展开。

同一页面内所有坐标、字号、描边和阴影使用统一设计空间。经营887×1774与局内928×1695分开计算viewport，切换时同步更新画布与输入变换。背景、绘制和点击共用等比 contain 变换，按安全区与实际胶囊预留空间；声音和设置位于左上。新增组件可按8／16／24／32设计像素组织间距，已定稿组件保留现有精确坐标与小数尺寸。

### 主界面共用规范

四个页签共享顶部棚沿、品牌标志、钱包、左上声音与设置、底部木质导航。首页的品牌与摊位较大；三个内容页收紧品牌区，以独立的木框奶油阅读面承托内容。页标题72、主按钮约45、物品名31～34、说明及状态25～29设计像素；首页“开张营业”69、关卡34。字号在887×1774画幅下定义，缩到手机后必须复核。数字、标题、页签和按钮文字均实时绘制，不拉伸字形。

- 深蓝绿环境提供纵深，蜂蜜木色负责承托，奶油面负责阅读；暖朱红集中在当前主操作及选中页签，不给每张卡加红底。
- 同级卡共用底面、圆角和柔和向下投影。卡片、图标、状态角标各自绘制，避免内容内反复套框。
- 四页底部导航位置和热区不变，当前项用浅奶油底与字重表示；导航整行不是一张图片。
- 钱包独立于品牌；大额数值可缩写为万／亿，账本保留完整金额。声音和设置位于左侧，钱包避让真实微信胶囊。素材不包含模拟胶囊。
- 购买、当前装备、选中试装三个状态分别表达；绿色勾表示已装备，朱红细边表示当前选中，“预览中”说明尚未保存。不可只靠颜色区分。

### 小摊：先看见自己的摊，再开张

视觉顺序为品牌 → 大摊位和大厨 → 下个愿望 → 开张营业 → 底部导航。场景为主体，保留完整棚布、立柱、木柜、灯笼、锅盘和前景凳子，人物面部不能被招牌或棚沿遮住。纯环境延续至页面下部，避免给场景额外套一块突兀的深色矩形。

“布置小摊”是轻量次操作；愿望是一张独立奶油卡，展示当前真实目标、拥有状态及金币进度。首页只突出一个朱红主按钮，关卡号作为按钮内第二层信息。查看关卡用轻文字入口，不与开张争夺注意力。

**注意：**环境图不得带中央摊位、人物、按钮或愿望卡。大厨、棚布、灯具、桌饰、摆件、菜单牌、锅、盘、背景九个可装扮位置必须独立。换单件只更新对应物件，不能把整个首页换成另一张截图。展示稿中的384金币、29关不是默认档案。

### 装扮：分类、试装和确认分清楚

结构为页标题 → 摊位／大厨／场景／主题 → 实时场景预览 → 部位分类 → 两列物品卡 → 确认动作。场景预览复用首页同一个组合器，按统一等比变换装入横框，不压扁人物或柜台。预览框的描边与“当前装扮／预览中”角标属于UI，不属于场景底图。

部位分类低于主分类一级；灯串、棚布、桌饰、摆件、招牌及翻组后的餐盘、炒锅都可到达。每页最多四件物品，卡片只为实际数据创建；缩略图展示独立物件，名称与状态清晰分区。选中未拥有物品可试看，但购买确认前不扣金币、不改装备；整套试装也不发放物品。

**注意：**空白容器素材里不能预画四张物品卡、分类按钮、红色购买条或“实时装扮效果”。这些全是可交互组件。已拥有、使用中、金币价格、通关条件、菜谱／夜市来源由真实配置决定；不能因参考稿只展示四件而丢掉剩余道具。相册及购买弹层也必须调用同一场景组合器。

### 菜谱：食物是主体，卡面只承托

结构为页标题与收集进度 → 菜谱／成就／相册 → 内容 → 翻页。菜谱保持两列三行，无夹子，不套材料卡；使用独立成品透明图、共用奶油卡、原生菜名与制作次数。20道菜全部按数据分页，最后一页只有实际剩余两道，不预画四个空卡框。菜名优先使用配置的短名，长文字省略或换行，不缩扁。

未收集用问号及“首次做成后点亮”明确说明；已经点亮的成品保持原色。成就用同级信息卡表达真实进度。相册只为真实照片／纪念创建缩略卡，空相册显示说明；照片按拍摄时的装备快照绘制，不跟随当前换装改变。

**注意：**成品图只包含食品及其餐盘，不得包含卡面、菜名或次数。禁止将前六道菜及其列表背景烘焙成整张图。各子页容器和按钮随内容创建，不能靠大色块遮住另一子页的固定图案。

### 夜市：氛围在横幅，规则在卡片

结构为页标题 → 当期／往期／每日 → 活动横幅 → 当前活动册大卡 → 其他册的紧凑行卡。横幅用独立环境、灯笼和实时文字组合，低对比环境衬亮字。当前册以大图标、册名、进度、奖励和一个主动作建立焦点，后续册降低权重；统一卡面和对齐线，避免四张卡同时高亮。

当前册与后续行卡使用同一份活动数据，开放条件、已完成、已选中和奖励状态分别表达。每日页用独立任务行，不在当期页面的固定底图上盖一层纸。往期保留已开放册，内容随真实记录变化。

**注意：**活动背景不得画死册名、进度条、按钮或四个列表槽。奖励在真实进度达到条件时自动发放，界面使用“查看已获奖励／继续营业攒进度”，不得引入手动领取或重复发放。参考稿周次和奖励仅作排版示例，实际开放期由配置计算。

### 资源边界与拼装规则

生产资源的最小边界是一个可复用的器物、材质或控件底面。组件可以包含自己的亮边、阴影和空白内页；固定柜台与立柱可为一个结构件。只要元素有独立交互、动态数据、换装、显示隐藏或动画，就必须独立。

| 层级 | 可包含 | 不可包含 |
| --- | --- | --- |
| 纯环境 | 夜街、水面、远摊、固定树木和环境灯光 | 中央可换装摊位、人物、钱包、按钮、卡片、进度条 |
| 场景物件 | 单个柜台结构、棚布、灯笼、大厨、凳子、锅盘、摆件 | UI边框、分类页签、当前价格／状态、其他装备部位 |
| UI底面 | 一个空白按钮／卡片／木框／选中页签的材质和阴影 | 兄弟控件、列表位置、成品、名称、价格和模拟状态 |
| 品牌 | 固定弧形五字“灯火大排档”及其木牌 | 钱包、页标题、关卡、系统胶囊 |
| 内容与反馈 | 独立食物、图标；代码绘制的文字、勾、进度和选中边 | 作为整页背景固定下来的一组交互内容 |

绘制顺序：纯环境 → 场景／内容父容器 → 子物件和卡片 → 图标与真实文字／状态 → 钱包和导航 → 弹层。场景内部使用统一设计空间，物件按contain等比绘制；透明开口保留alpha。按钮与卡片采用九切片，只伸展空白中心和边条，圆角与高光不拉长。大容器的弧顶由其自身上部切片保留，内部布局不随图片缩放。

资源清单位于`shared/assets/lobby/manifest.json`，独立源图位于`source/ui/`、`source/scene/`、`source/brand/`、`source/icons/`。`prepare-lobby-assets.py`仅按清单缩放、压缩和导出颜色变体，不读取参考稿、不裁整页坐标、不合成页面。页面坐标在`lobby-layout.js`，共用底面在`lobby-components.js`，场景在`lobby-scene.js`，功能组装在`lobby-ui.js`。四张完整视觉稿只放在`reference/`作对照，不进入运行包。

主题可改变夜色和九个装扮部位，保持奶油信息面、食物原色和深棕文字。颜色变体只作用于对应衣料／棚布／凳子，不改变肤色、木纹、金属、绿叶和其他装备；背景与独立前景重新组合。主题不移动关键操作，不改变奖励、容量、配方或时间规则。

## 动效语言

动效表现器物的轻抬、落稳、收起、颠锅和上菜：短、柔和、有方向，反馈与真实操作和状态对应。避免持续大幅弹跳、无意义旋转、全屏闪光，以及等待动画结束才允许继续操作。

- 取牌沿弧线飞向备菜格，卡面尺寸平滑变化，食物保持等比；点击圈只作反馈。
- 收到食材时绿勾轻弹，食物保持原色；交单后才出现盘盖，随后整卡收起，新单轻落。
- 制作依靠颠锅、碎料和轻蒸汽表达热气；上菜副本独立飞行，收入在真实送达后轻弹。
- 小反馈控制在约0.16～0.30秒；收入回弹峰值仅1.018。弹窗约0.34秒从0.94缩放至1，配合淡入。
- 减少动效时保留结果和状态辨识，降低位移、旋转与粒子运动；暂停和后台冻结表现。

闯关各阶段的精确时长、路径、图层与并发规则只在[菜单交接时序和表现](10-menu-handoff.md)维护。新页面延用手感，不复制演示常量或另外引入阻塞业务的动画等待。

## 交付检查

新增界面完成后，至少核对以下项目：

1. 与当前闯关并排查看，奶油色、木色、墨色、圆角、亮边、阴影和图标属于同一套风格；主招牌仍为五字。
2. 主内容与主操作清楚，装饰不遮挡信息；已收、选中、锁定和不可用状态可以区分。
3. 图片和文字不拉伸，食物清晰，长文案不溢出；在手机尺寸查看字号与实际点击范围。
4. 检查正常、选中、不可用、空内容和弹窗状态，以及减少动效后的状态辨识；页面只检查实际存在的功能状态。
5. 单独查看每张生产素材：按钮不含文字、卡面不含列表、环境不含功能；改变列表数量、页签和单件装备时无旧图残留。
6. 浏览器和微信使用同一设计坐标与资源，核对安全区、胶囊、触摸、遮挡关系和重复叠画；自动截图不能代替真机验收。

更改统一视觉基准时，同步修订本文及相关实现，替换过时规则；精确闯关时序同步维护10文档，产品功能变化同步维护11、12文档。
