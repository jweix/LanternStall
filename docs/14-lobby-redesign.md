## 四页结构

- **小摊：**纯环境上组装大摊位，愿望卡、布置入口和朱红开张按钮分别创建。没有把这些操作印在环境里。
- **装扮：**木框内容面、主分类、实时预览、部位分类、两列物品卡、确认按钮逐层创建。每页最多四件，只绘制实际数据；七个摊位部位加大厨、背景全部可达。
- **菜谱：**独立成品图＋共用奶油卡＋名称／次数，两列三行分页；20道全部同一规则，末页只有两道。成就和相册使用各自的数据列表，空内容不留下固定卡框。
- **夜市：**活动横幅由环境、灯笼和活动文字组合；当前册大卡、其他册行卡、任务行与按钮均为独立组件。切换当期／往期／每日不会靠不透明色块遮住其他页面的预画内容。

导航使用一块公共木质承托，四个图标、当前项底面、名称和热区分别创建。按钮按真实状态决定能否点击，命中范围就是实际控件范围；弹层阻断底层命中。

## 画幅、缩放与图层

经营页设计887×1774，闯关928×1695，各自统一等比contain。浏览器同步切换Canvas、CSS比例、输入换算和无障碍控件。微信由`renderer.coordinates(geometry,screen)`取得同一变换，经营从状态栏安全区下开始，钱包进一步避让真实胶囊，局内保持既有避让。生产图片中没有模拟胶囊。

环境使用cover，场景物件使用contain；场景整体再等比装入预览框。控件用九切片保留边角，中心随容器延展；不能把整张页面拉宽、把人物压扁或按截图坐标裁下整排按钮。层级为环境、场景／父容器、子控件、内容状态、钱包导航、弹层。透明开口和圆角必须真正透明。

## 原稿示例与真实规则

1. 原稿384金币、29关、制作次数与20/20仅为展示值，启动仍是玩家本机真实档案；不注入示例进度。
2. 钱包大额余额可用万／亿缩写，账本保留完整金额；愿望是实际选择的单件，不强制变成背景解锁。
3. 实际价格、1／20／40关门槛、赠品来源等继续读取`progression.js`，不覆盖经济配置。
4. 活动奖励在达到进度时自动发放；UI使用“查看已获奖励／继续营业攒进度”，不新增手动领取。查看定位到真实已拥有装备。
5. 主题可试看整套，单件购买和装备仍独立；相册按拍摄时的装备快照绘制，拍照入口在相册。
6. 无音频素材时声音入口如实说明；设置中的减少动效继续有效。金币、存档、配方、厨房、闯关规则未改变。

## 构建与核对

```sh
npm run build:wechat
npm test
npm run serve
```

微信开发者工具导入`platforms/wechat/`，不手改生成的`game/`。两端共享142张运行图，主包约2.63MiB，低于工程4MiB预算；构建同时移除旧整页运行图。源组件留在工程，参考稿、源图和预览不进入主包。

具备`@napi-rs/canvas`时运行`node scripts/render-lobby-preview.cjs`；可用`LANTERN_CANVAS_MODULE`指定模块。该脚本以隔离档案完成28次真实引擎通关及9次购买，生成[四页](../previews/lobby-v4-overview.png)、[主题试装](../previews/lobby-v4-themes.png)、[购买弹层](../previews/lobby-v4-purchase.png)和[资源拆分图](../previews/lobby-v4-components.png)，不修改玩家存档。[浏览器首页](../previews/lobby-v4-browser-home.jpg)使用实际新档状态。

`verify-lobby.cjs`覆盖四页命中、九部位、真实扣款、隔离试装、分页、末页卡数、场景单件替换、资源边界与参考图完整性；微信测试覆盖资源一致及原生安全区／触摸变换。验收同时查看独立组件和实际页面，不能仅检查一张最终截图。文字使用系统字体回退，微信真机字体、DPR、触摸和性能仍需实机核对；自动通过不等于所有设备逐像素一致。
