# 项目现状与接手记录

2026-11-12 整理。先阅读《灯火大排档制作交接说明》，再核对源码和独立素材。用户已纠正原包中的规则：**没有收入目标；清空全部食材并完成最后一道菜上菜后通关。** 该规则已写入业务、界面、自动验证、文字规范及交接文档。

## 原包实际完成的内容

- 20 道菜：10 道双食材、10 道三食材；14 种独立透明食材。双料按基础价，三料按基础价 ×1.5。配方不从菜名或图片推断。
- `game-core.js` 管理收料、7 格容量预约、自动配方消费、炒锅 FIFO、独立上菜、换单、收入和道具；`motion.js` 提供设计坐标与动效计算。原包的 12 项核心验证通过，原始素材哈希一致。
- 两个离线 HTML 分别展示 v13 的固定时间轴和单菜素材链路。它们有点击反馈，但不是玩家自由操作的完整关卡。
- 原包没有微信 `game.js`、`game.json`、项目配置、平台生命周期、存档或经过验证的真实关卡。

## 本次整理与接入

公共业务、布局、素材移入 `shared/`；原浏览器代码与 base64 数据移入 `platforms/web/`。微信独有调用集中在 `platforms/wechat/src/`，构建生成可独立导入的包。原始资源未修改，压缩资源可重建。

真实试玩从收入 0 开始。每关 40 张牌，保留 5×5 上层和 15 张偏移下层，通过几何遮挡判断能否选取。每关选三种兼容菜谱，混合双料和三料，生成完整可解路径；关卡轮换覆盖素材库。此生成方式保证存在解，并未证明随机操作或任意顺序都能通关。

通关必须满足：牌堆已取空；备菜、入槽飞行、暂存均为空；炒锅、排队和送菜任务均完成。最后上菜时结算并冻结用时，0.6 秒后显示成功弹窗。收入不影响成败，空的新订单不妨碍通关。

选牌飞行不锁住后续点击，入槽后匹配配方；配齐立刻释放槽位，出锅立刻释放炒锅。各桌独立刷新。工具有次数限制；暂存内容在食材台右下角显示，点击取回。

微信适配包括图片加载及失败重试、安全区与原生胶囊避让、DPR 渲染、触摸逆变换、后台暂停和返回重置帧时间。本地只保存解锁关卡和减少动效设置。当前静音，没有登录、联网接口或商业化接入。

## 验证与边界

`npm run build:wechat` 生成约 3.21 MiB 的独立主包。`npm test` 覆盖原有 12 项验证、100 个确定性牌堆完整通关、7 次快速输入与第 8 次拒绝、收入不触发通关、最后上菜后结算、暂存、失败、暂停、重开、换关和微信无 DOM 启动模拟。

已在微信开发者工具 2.02.2608080、基础库 3.18.0 中导入，实际编译和整屏绘制通过，控制台没有脚本错误。修正了微信不能直接 require JSON，以及胶囊信息缺少 bottom 时导致画面缩放异常的问题。自动化鼠标点击未能触发模拟器的原生输入回调；触摸逆变换和设置响应由微信入口模拟测试覆盖，真机触摸尚未验证。

浏览器实际点选番茄和鸡蛋后成功自动做菜、上菜，收入由 0 变为 32，并独立补单；控制台没有运行错误。两个旧展示页和 20 道菜图片迁移后加载正常。

真机适配、性能、音频、正式关卡难度、账号与审核发布仍需继续制作。旧底图中的动态区域已由代码覆盖，但生产美术仍建议拆成纯背景图层。

原始文件清单、验收报告和起读说明归档于 `docs/handoff/`，其中路径和通过记录属于交接时的历史状态，不是本次验证结果。`reference/` 的图片视频保持原样，旧的收入分母不代表现行规则。
